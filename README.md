# necropsy

Вскрытие бинарников: свой разборщик ELF (и позже PE) на Go без внешних зависимостей, паттерны ImHex, учебные программы на x86-64 assembly и решения на pwntools. Работа только с собственными учебными бинарниками и файлами, которые вы вправе исследовать.

Статус: ранняя версия. Готов разбор ELF; PE, учебные бинарники и паттерны ImHex в планах (см. [CHANGELOG](CHANGELOG.md)).

## Быстрый старт

```bash
go build -o bin/necropsy ./cmd/necropsy
bin/necropsy inspect ./некий-elf-файл          # заголовок, зависимости, защита, секции с энтропией
bin/necropsy inspect --json ./некий-elf-файл   # то же в JSON
go test ./...
```

Что показывает `inspect` для ELF 32/64 (little-endian): архитектуру и тип, точку входа, интерпретатор и `DT_NEEDED`, RUNPATH, сегменты и секции с энтропией по Шеннону, а также сводку в духе checksec: PIE, NX, RELRO (none/partial/full), канарейка стека, `_chk`-функции (fortify), stripped, статическая линковка, сегменты RWX. Предупреждения: секция с энтропией выше 7,2 (упаковано или зашифровано?), исполняемый стек, RUNPATH. Сжатые секции `.debug_*` под это предупреждение не попадают.

## Как проверялось

- Разборщик написан с нуля, а стандартная `debug/elf` используется **только в тестах как эталон**: на реальных бинарниках Go для amd64, arm64 и 386 совпадают заголовок, все сегменты, все секции и число символов.
- Обрезанные и испорченные файлы (сотни вариантов) не вызывают паники и зависания. Все чтения идут с проверкой границ, числа из заголовков ограничены.
- `go vet` и тесты в CI.

## Ограничения

- Только little-endian ELF. Big-endian отклоняется с ошибкой.
- Оценка «канарейка» и «fortify» строится по именам символов, поэтому у stripped-файлов она может быть неточной.
- Сверка с эталоном шла на бинарниках Go; на файлах, собранных gcc/clang с динамической линковкой, проверено только на ручных заголовках, а не на реальном образце.
- Это учебный инструмент, он не заменяет `readelf`, `checksec` и Ghidra.
