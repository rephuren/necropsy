# Лаба 01 — ret2win

**Цель:** увести адрес возврата на уже существующую функцию `win()`.

Вызов `read()` намеренно принимает больше байтов, чем помещается в `buffer[64]`. Задача локальная и собрана без канарейки стека и без PIE. NX остаётся включённым — внедрять код не нужно.

Соберите `make`, затем запустите `python3 exploit.py`. Скрипт на pwntools собирает полезную нагрузку под поставляемую сборку. Смещение в 72 байта соответствует этой компиляции и раскладке кадра; при смене флагов компилятора или исходника посмотрите дизассемблер.

**Вопросы для разбора:** почему NX не мешает ret2win? Что меняется при включённых PIE или канарейке стека? Зачем на amd64 нужен «пустой» гаджет `ret` для выравнивания стека?
